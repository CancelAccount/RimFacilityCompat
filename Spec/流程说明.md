# RimFacilityCompat 流程说明

> 本文档描述当前架构（单通道运行时声明式注入），已于 2026-09-07 实施完成。
> 旧版「生成 XPath 补丁文件 → 重启生效」的双通道架构已废弃，相关代码（`XpathGenerator.cs`、
> `CleanupComps()`、`PatchTarget()`、`enableRuntimePatch`、`savedXXX`）已删除。

---

## 整体架构

```
游戏启动（LongEventHandler.ExecuteWhenFinished，主菜单出现前）
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段一：扫描（干净 defs，未被任何注入修改）                     │
│  FacilityScanner.ScanAll() → categories                     │
│  ScanOriginalLinks()      → originalLinks（真原始）           │
│  SnapshotOriginalComps()  → 原版自带 comp 的目标快照           │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段二：首次运行初始化（仅一次）                               │
│  未初始化 → ResetToOriginal()（保守语义：仅保留原始链接）        │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段三：声明式注入 ApplyInjection() + Write()                 │
│  每个目标的 linkableFacilities ≡ 配置声明状态（整体重建）      │
└─────────────────────────────────────────────────────────────┘

设置界面操作（勾选 / 断开 / 重置 / 粘贴 / 导入 / 全局操作）
    │
    ▼
ApplyAndSave() = ApplyInjection() + RelinkSpawnedThings() + Write()
    → 当次会话即时生效，无需重启

存档加载 / 新游戏 / 建筑生成（引擎自动，无需本 mod 参与）
    │
    ▼
CompAffectedByFacilities.PostSpawnSetup → LinkToNearbyFacilities()
    → 已放置建筑按当前 defs 自动重连
```

## 一、启动流程

### 入口

[FacilityPatcher.cs](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/Pipeline/FacilityPatcher.cs) `Apply()`，由 `[StaticConstructorOnStartup]` 注册，`LongEventHandler.ExecuteWhenFinished` 在主菜单出现前执行。

### 阶段一：扫描

```
settings.categories = FacilityScanner.ScanAll();
settings.originalLinks = ScanOriginalLinks(settings.categories);
SnapshotOriginalComps(settings.categories);
```

- **扫描基准干净**：运行时注入不落盘，每次启动 defs 自动回到 XML 原始状态，`originalLinks` 与连通分量分组天然基于真原始状态。
- **原版 comp 快照**：`SnapshotOriginalComps` 记录「哪些目标在 XML 里本来就带 `CompProperties_AffectedByFacilities`」，供注入阶段区分原版 comp 与运行时新建 comp。

### 阶段二：首次运行初始化

`initialized` 为持久化标志，首次为 `false` 时执行一次 `ResetToOriginal()`（保守语义：仅保留原始链接），随后置 `true` 持久化。

### 阶段三：声明式注入 + 落盘

`ApplyInjection()` 重建全部目标，随后 `Write()` 落盘（确保 `initialized` 持久化）。

## 二、核心注入逻辑

### 入口

[FacilityPatcher.cs](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/Pipeline/FacilityPatcher.cs) `ApplyInjection(FacilityCompatSettings settings)`。

### 语义：声明式重建（双向）

每个目标的最终 `linkableFacilities ≡ 配置声明状态`（类别下所有设施 ∩ 白名单启用的集合），**整体重建而非增量追加**：

```
对每个类别：
  allFacilityDefs = 类别下全部设施 def（GetNamedSilentFail 过滤失效 defName）

  对每个目标 def：
    finalList = allFacilityDefs.Where(ShouldLink(配置))

    若 finalList 为空：
      原版 comp → 仅清空 linkableFacilities（保留结构）
      自建 comp → 从 def.comps 整体移除
    否则：
      无 comp → 新建 CompProperties_AffectedByFacilities 并加入 def.comps
      comp.linkableFacilities = finalList（整体重建）

  对 linkableFacilities 发生变化的目标涉及的设施 def（旧∪新列表）：
    CompProperties_Facility.ResolveReferences(facilityDef) → 重建 linkableBuildings
```

### 设施侧反向索引（linkableBuildings）必须同步重建

RimWorld 1.6 的设施连接是**双向声明**：除目标侧 `linkableFacilities` 外，设施 def 上还有反向索引 `CompProperties_Facility.linkableBuildings`（"可连接的目标"列表），仅在 **def 加载时**由引擎 `ResolveReferences` 扫描所有目标的 `linkableFacilities` 反向填充一次。设施侧全部入口都读该索引：

| 入口 | 路径 |
|---|---|
| 设施蓝图预览连线 | `PlaceWorker_ShowFacilitiesConnections.DrawGhost` → `CompFacility.DrawLinesToPotentialThingsToLinkTo` |
| 设施蓝图放置提示 | `PlaceWorker_ShowFacilitiesConnections.DrawPlaceMouseAttachments` → `CompFacility.DrawPlaceMouseAttachmentsToPotentialThingsToLinkTo` |
| 设施放置/重装连接 | `CompFacility.PostSpawnSetup` → `LinkToNearbyBuildings` |
| 目标建造菜单 | `BuildFacilityCommandUtility`（读目标侧，不受影响） |

运行时修改目标的 `linkableFacilities` 不会自动重算反向索引——若不同步重建，补丁连接对设施侧不可见（**表现为：放设施蓝图不画线、建成不连接，必须重放主设施才生效**，因主设施侧走 `linkableFacilities`）。修复：注入后对受影响设施调用引擎的 `ResolveReferences`（全量扫描 defs 按"当前所有目标"重建，与其他 mod 的声明天然兼容）。重建前做集合语义的变更检测，未变化的目标不覆盖引用、不触发重建。

### 带来的性质

- **增删皆可**：原始链接也能被断开。
- **幂等**：重复调用结果一致，无重复条目。
- **单 comp 唯一**：只新增、不追加同类 comp。
- **不落盘**：每次启动 defs 自动干净。

## 三、设置界面即时生效

### 入口

[Dialog_FacilityMatrix.cs](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/UI/Dialog_FacilityMatrix.cs) `ApplyAndSave()`：

```
ApplyAndSave() = FacilityPatcher.ApplyInjection(settings)
               + FacilityPatcher.RelinkSpawnedThings()
               + settings.Write()
```

> 重连采用**直接调用**而非事件监听：修改源已收敛于 `ApplyAndSave` 单一入口（单生产者-单消费者，
> 事件是无意义的中间层），且必须严格保证「注入 def → 重连建筑」先后顺序（时序确定性）。
> 设置界面期间游戏自动暂停，遍历重连无卡顿风险。

所有改动点统一走此入口，当次会话即时生效：

| 改动点 | 位置 |
|---|---|
| 单击切换连接 | `OnCellClick` |
| 批量拖拽（退出批量时） | `ExitBatchMode` |
| 单项重置（双侧） | 底部栏「重置」按钮：附属设备 → `ResetFacilityToOriginal`；主设施 → `ResetTargetToOriginal` |
| 全部启用 / 全部禁用 | `ApplyToSelection` |
| 复制 / 粘贴（双侧） | `CopySelected` / `PasteToSelected` 按选中侧分派：附属设备 → 连接配置（`FacilityClipboard.Direction.Facility`）；主设施 → 连接模式（`Direction.Target`），两维度互不通用 |
| 全局重置 / 预设导入导出 | `Dialog_PresetManager`（右下「全局操作」按钮打开，替代原 `BuildGlobalMenu` 多层 FloatMenu） |

> 重置/复制/粘贴按钮曾仅附属设备侧可用（`active: SelSide == Accessory`）——1.6 的
> `Widgets.ButtonText` 对 inactive 按钮不做灰显（`ButtonTextWorker` 直接返回 Idle），
> 选中主设施时按钮外观正常但点击被静默吞掉，表现为"按下无反应"。现已双侧支持。

> 批量拖拽过程中只改内存 `settings`（`ApplyBatch`），落盘延迟到退出批量模式时统一执行，避免每帧写盘卡顿。
> 无独立「保存并应用」按钮——配置改动已即时注入并落盘。

## 四、已放置建筑重连

### 引擎自动重连（读档 / 新游戏 / 建筑生成）

`CompAffectedByFacilities` 未持久化 `linkedFacilities`（无 `ExposeData`）。读档与新游戏时所有建筑经 `SpawnSetup → PostSpawnSetup(respawningAfterLoad)` 自动调用 `LinkToNearbyFacilities()` 按当前 defs 全量重连；建筑生成时同理。**引擎已覆盖该场景，本 mod 无需参与**（原 `FacilityGameComponent` 因此冗余，已删除）。

### 会话中修改配置（本 mod 补齐）

def 层重建不会触发已放置建筑重连。[FacilityPatcher.cs](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/Pipeline/FacilityPatcher.cs) `RelinkSpawnedThings()` 遍历当前会话所有地图的 `CompAffectedByFacilities`，调用 public 的 `Notify_ThingChanged()` 触发 `RelinkAll()`，使已放置建筑立即应用新配置。由 `ApplyAndSave()` 在注入后直接顺序调用。

> 遍历重连对每个建筑的同类设施做全量距离排序，复杂度与地图规模相关；但设置界面期间游戏自动暂停，无卡顿风险。

## 五、数据层

[Settings.cs](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/Data/Settings.cs) 关键成员：

| 成员 | 说明 |
|---|---|
| `linkedTargets` | 白名单，key = `"类别|设施defName"`，value = 启用的目标 defName 集合（序列化）。无 key 或空 = 不连接任何目标 |
| `categories` | 扫描结果（不序列化，每次启动重建） |
| `originalLinks` | 原始链接快照（不序列化） |
| `initialized` | 首次初始化标志（序列化，字段名 `initializedV2`） |

`ShouldLink()` 默认返回 `false`（白名单语义）：无记录即不连接。`GetMode()` 的 None 判定按「无白名单记录或记录为空」；All = 全部有效目标（过滤失效 defName）均启用；Manual = 部分启用。`ResetToOriginal()` 将白名单重置为原始链接（`originalLinks`）。
