# RimFacilityCompat 流程说明

## 整体架构

```
游戏启动
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段一：扫描 (FacilityScanner.ScanAll)                      │
│  遍历所有 ThingDef，按 thingClass 分类收集设施和目标           │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段二：运行时处理 (FacilityPatcher.Apply)                   │
│  清理合并 → 可选运行时注入 → 检查/生成 XML 补丁文件           │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段三：XML 生成 (XpathGenerator.Generate)                  │
│  按分组策略生成 FC_Generated.xml 补丁文件                     │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│  阶段四：XPath 注入（游戏重启后）                              │
│  RimWorld 加载 Patches 目录，应用生成的 xpath 补丁             │
└─────────────────────────────────────────────────────────────┘
```

## 阶段一：扫描 (FacilityScanner)

### 入口
[FacilityScanner.cs:40](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/FacilityScanner.cs#L40) `ScanAll()`

### 流程

```
遍历所有 ThingDef
    │
    ├─ 筛选：thingClass != null && 
    │        thingClass != Building && 
    │        comps 包含 CompProperties_AffectedByFacilities
    │
    ├─ 按 thingClass.Name 分类（如 Building_Bed、Building_WorkTable）
    │
    ├─ 将该 def 加入对应类别的 targets 列表
    │
    └─ 遍历 CompProperties_AffectedByFacilities.linkableFacilities
        │
        └─ 将设施按 mod 来源分组，加入 info.facilities
```

### 输出数据结构

```csharp
// CategoryInfo
{
    displayName: "床",           // 分类显示名（翻译后）
    thingClassName: "Building_Bed",
    targets: [                  // 该类别的所有目标建筑
        { defName: "Bed_Simple", label: "简易床", source: "VFE" }
    ],
    facilities: {               // 设施按 mod 来源分组
        "Core": ["EndTable", "Dresser"],
        "VFE": ["VFE_RoyalWardrobe"]
    }
}
```

### 关键设计
- **thingClass 作为分类依据**：同类建筑共享相同的设施链接规则
- **设施按 mod 分组**：便于用户按来源管理
- **翻译支持**：类别名通过 `KnownCategoryKeys` 映射到翻译 key

## 阶段二：运行时处理 (FacilityPatcher)

### 入口
[FacilityPatcher.cs:19](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/FacilityPatcher.cs#L19) `Apply()`

### 执行时机
`LongEventHandler.ExecuteWhenFinished` —— 在所有 Def 加载完成后执行

### 子阶段 2.1：扫描与数据填充

```
settings.categories = FacilityScanner.ScanAll();
settings.originalLinks = ScanOriginalLinks(categories);  // 记录原始链接

// 填充 targets 详细信息（用于设置界面）
foreach 类别:
    查询 DefDatabase 获取所有目标 ThingDef
    构建 BuildingTarget（含 mod 来源）
```

### 子阶段 2.2：清理合并（始终执行）

[FacilityPatcher.cs:122](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/FacilityPatcher.cs#L122) `CleanupComps()`

```
遍历所有目标 ThingDef:
    │
    ├─ 查找所有 CompProperties_AffectedByFacilities
    │
    ├─ 如果数量 > 1 → 合并为一个（去重 linkableFacilities）
    │
    └─ 清理 null 条目（mod 移除后遗留）
```

**设计意图**：修复 xpath 补丁可能产生的重复 comp，确保运行时数据一致性

### 子阶段 2.3：C# 运行时注入（可选）

[FacilityPatcher.cs:164](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/FacilityPatcher.cs#L164) `PatchTarget()`

**触发条件**：`settings.enableRuntimePatch == true`

```
遍历所有目标 ThingDef:
    │
    ├─ 获取或创建 CompProperties_AffectedByFacilities
    │
    ├─ 移除被用户排除的设施（根据设置中的 excludedTargets）
    │
    └─ 添加用户启用但缺失的设施
```

**局限性**：运行时注入在蓝图阶段不可见，建造设施时不会立即检测到链接关系

### 子阶段 2.4：XML 补丁文件检查

```
检查 FC_Generated.xml 是否存在:
    │
    ├─ 不存在：
    │   │
    │   ├─ 首次运行 → ResetToOriginal() + SaveForXpath()
    │   │
    │   └─ XpathGenerator.Generate() → 生成补丁文件
    │       输出警告：需要重启游戏生效
    │
    └─ 存在：跳过（使用已有补丁）
```

## 阶段三：XML 补丁生成 (XpathGenerator)

### 入口
[XpathGenerator.cs:23](file:///e:/steam/steamapps/common/RimWorld/Mods/RimFacilityCompat/Source/XpathGenerator.cs#L23) `Generate()`

### 数据来源

| 数据项 | 来源 | 说明 |
|--------|------|------|
| savedCategories | settings | 上次保存的分类配置 |
| savedFacilities | settings | 上次保存的设施列表 |
| savedTargets | settings | 上次保存的目标列表 |

### 分组策略

```
按目标是否有 CompProperties_AffectedByFacilities 分为两组：

defsWithComp:
    目标已有该 comp（运行时检测）
    → 操作1：追加到已有的 linkableFacilities

defsWithoutComp:
    目标没有该 comp
    → 操作2：创建新的 CompProperties_AffectedByFacilities
```

### 操作1：追加到已有 linkableFacilities

**XPath 路径**：
```
/Defs/ThingDef[defName="目标defName"]/comps/li[@Class="CompProperties_AffectedByFacilities"]/linkableFacilities
```

**生成的补丁结构**：
```xml
<Operation Class="PatchOperationConditional">
  <xpath>/Defs/ThingDef[defName="Bed_Simple"]/comps/li[@Class="CompProperties_AffectedByFacilities"]/linkableFacilities</xpath>
  <match Class="PatchOperationAdd">
    <xpath>/Defs/ThingDef[defName="Bed_Simple"]/comps/li[@Class="CompProperties_AffectedByFacilities"]/linkableFacilities</xpath>
    <value>
      <li>EndTable</li>
      <li>Dresser</li>
    </value>
  </match>
</Operation>
```

**适用场景**：VFE 等 mod 的床，直接继承 Core 的 `BedBase`，`CompProperties_AffectedByFacilities` 在 XML 中可见

### 操作2：创建新的 CompProperties_AffectedByFacilities

**XPath 路径**：
```
/Defs/ThingDef[defName="目标defName"]/comps
```

**生成的补丁结构**：
```xml
<Operation Class="PatchOperationConditional">
  <xpath>/Defs/ThingDef[defName="RI_Building_SleepingBed"]/comps</xpath>
  <match Class="PatchOperationAdd">
    <xpath>/Defs/ThingDef[defName="RI_Building_SleepingBed"]/comps</xpath>
    <value>
      <li Class="CompProperties_AffectedByFacilities">
        <linkableFacilities>
          <li>EndTable</li>
          <li>Dresser</li>
        </linkableFacilities>
      </li>
    </value>
  </match>
</Operation>
```

**适用场景**：目标没有 `CompProperties_AffectedByFacilities`，需要从头创建

### 关键设计

1. **defName 精确匹配**：避免 thingClass 继承导致的匹配问题
2. **PatchOperationConditional 保护**：目标不存在时静默跳过
3. **按类别批量注入**：同类设施一次性追加，减少补丁数量

## 阶段四：XPath 注入（游戏重启后）

### 触发时机
游戏重启后，RimWorld 加载所有 mod 时：

```
加载顺序（RimWorld 内置）:
    1. 加载所有 mod 的 Defs 目录（按 mod 列表顺序）
    2. 应用所有 mod 的 Patches 目录（按 mod 列表顺序）
```

### 补丁应用流程

```
RimWorld 读取 FC_Generated.xml
    │
    ├─ 解析 <Patch> 根节点
    │
    ├─ 逐个执行 <Operation>
    │   │
    │   ├─ PatchOperationConditional:
    │   │   │
    │   │   ├─ 执行 xpath 匹配
    │   │   │
    │   │   └─ 匹配成功 → 执行 <match>
    │   │      匹配失败 → 跳过（静默）
    │   │
    │   └─ PatchOperationAdd:
    │       │
    │       └─ 在指定 xpath 位置追加 <value> 内容
    │
    └─ 补丁生效，目标 ThingDef 的 linkableFacilities 被修改
```

### 关键注意事项

| 注意点 | 说明 |
|--------|------|
| **加载顺序** | RimFacilityCompat 必须放在所有目标 mod 之后，否则目标 Def 尚未加载，xpath 匹配失败 |
| **继承展开** | XPath 阶段，RimWorld 会展开 Abstract 继承，但多层继承可能导致节点不可见 |
| **静默失败** | `PatchOperationConditional` 匹配失败时不会报错，需通过日志排查 |
| **重复注入** | 如果同时使用操作1和操作2（或多次生成），可能产生重复 comp，由 `CleanupComps` 兜底 |

## 首次运行完整流程

```
第一次启动游戏:
    │
    ├─ 阶段一：扫描 → 获取 categories/facilities/targets
    │
    ├─ 阶段二：
    │   │
    │   ├─ 填充 targets 信息
    │   │
    │   ├─ CleanupComps() → 清理（通常无操作）
    │   │
    │   └─ FC_Generated.xml 不存在 → ResetToOriginal() + Generate()
    │       │
    │       └─ 输出警告：需要重启游戏
    │
    └─ 用户看到设置界面，可以修改配置

第二次启动游戏（重启后）:
    │
    ├─ RimWorld 应用 FC_Generated.xml 的 xpath 补丁
    │   │
    │   └─ 目标建筑的 linkableFacilities 被修改
    │
    ├─ 阶段一：扫描 → 读取已注入的设施链接
    │
    ├─ 阶段二：
    │   │
    │   ├─ 填充 targets 信息
    │   │
    │   ├─ CleanupComps() → 合并可能的重复 comp
    │   │
    │   └─ FC_Generated.xml 已存在 → 跳过生成
    │
    └─ 用户可以放置建筑，设施链接正常工作
```
