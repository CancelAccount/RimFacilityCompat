# RimFacilityCompat 作者预设预设库（内置）— 轻量增量方案

> 文档版本：v1.2（2026-09-07）
> 状态：方案定稿，待实施
> 产品决策（用户确认）：
> - 注入模型：**轻量增量**——保留现有 `excludedTargets` 排除表与 UI 全栈不动
> - 语义来源：v2 语义表 preset（`<Link Target Facility/>`），导入=对每条 Link 增量启用（解除排除），导出=按来源过滤当前启用连接集
> - 应用方式：**仅手动导入**
> - 组合校验：**沿用现有 Import 方法**（def 存在性 + comp 存在 + 类别归属），不做位置级预判（位置约束由引擎放置时自然生效）
> - 目标场景：鼠族等种族提供生产目标，VFE 等提供链接设施；连接关系由 preset 语义表逐对声明

---

## 1. 背景：为什么推荐语义表（而非类别池全注入）

当前注入是「类别内全部目标 × 全部设施」矩形：`ShouldLink = 不在排除表`。
但各类 mod 声明五花八门，类别池过宽导致乱配（缝纫台连锻造柜），VFE 用自身 Connections.xml patch 原版而不会 patch 第三方种族导致漏配（鼠族缝纫台连不上 VFE_TailorCabinet）。

**结论**：把「原版/VFE 未覆盖的跨 mod 精确组合」交由**语义表 preset 逐对声明**。扫描类别仅承担 UI 分组与导入校验。

行为等价性说明：`ResetToOriginal` 后每目标仅连原始链接，此后每条启用（=从排除表移除一对）就是白名单增量——**现有排除表已天然承载白名单语义**，无需翻转为 `linkedTargets`。

---

## 2. 数据模型（沿用现状，零重构）

| 组件 | 说明 |
|---|---|
| `excludedTargets` | 不变。key=`"类别\|设施defName"`，value=排除的目标列表 |
| `originalLinks` | 不变。「全部重置」回到原始状态 |
| `SetLink / ShouldLink` 等 | 不变 |
| 来源标识 | `BuildingTarget.sourceMod` 与 `CategoryInfo.facilities` 的 key = modContentPack.Name/翻译名，按来源导出即按它过滤 |

---

## 3. 预设格式 v2（语义表）

```xml
<FacilityCompatPreset Version="2" Name="鼠族生产适配包">
    <Link Target="RK_ElectricTailoringBench" Facility="ToolCabinet" />
    <Link Target="RK_ElectricTailoringBench" Facility="VFE_TailorCabinet" />
</FacilityCompatPreset>
```

**语义**：
- 一条 `<Link>` = 「该目标应当连接该设施」；
- **导入**：反查 (类别,设施,目标)，调用 `SetLink(category, facility, target, true)`（解除排除）→ 幂等 union，缺 def 自动跳过计数；
- **导出（按来源）**：遍历全部类别，取 `sourceMod == 所选来源` 的目标，收集其当前**启用**（未排除）的设施对，写为 `<Link>`。作者在游戏内把鼠族缝纫台连好缝纫柜后导出的文件，天然只含“缝纫台→工具柜/缝纫柜”这类语义正确的对；
- **统一 v2、废弃 v1**：趁 mod 未发布，全格式统一为 `<Link>` 声明语义，不再解析旧 `<Exclude>`，减少维护成本。

## 4. 预设包与内容生产流程

| 步骤 | 谁 | 内容 |
|---|---|---|
| 机制落地 | 开发者 | 本方案 §5 清单 |
| 内容制作 | **用户（游戏内）** | 装好鼠族+VFE → UI 点选「鼠族缝纫台 ↔ VFE_TailorCabinet」等 → 导出按来源（鼠族）→ 生成 `FC_Recommended_Ratkin.xml` |
| 校验/入库 | 用户 | 用 P 测试清单验证后随发行放进 `{modDir}/Presets/` |

预设包（手动导入，文件随发行只读）：

| 包 | 文件 | 内容方向 |
|---|---|---|
| P1 鼠族整合 | `FC_Recommended_Ratkin.xml` | 鼠族/鼠族扩展生产目标 → VFE 柜类/Rimkea/仙路适用设施 |
| P2 绮罗整合 | `FC_Recommended_Kiiro.xml` | 同上 |
| P3 米莉拉整合 | `FC_Recommended_Milira.xml` | 同上 |
| P4 萌螈整合 | `FC_Recommended_Amby.xml` | 同上 |
| P5 通用补全 | `FC_Recommended_Generic.xml` | 原版/跨种族通用 |

内容规则：凡目标 XML 已声明的不重复写；只补「缺的」（VFE_TailorCabinet 等）。

## 5. 代码变更清单（轻量增量）

| 文件 | 变更 |
|---|---|
| `FacilityPreset.cs` | ① `Export` 支持按来源过滤（参数 `sourceMod`，null=全量 v1 备份）：收集该来源目标当前启用设施对 → 写 v2 `<Link>`；② `Import` 统一为 v2 `<Link>` 解析：反查类别+def/comp 校验 → `SetLink(..., true)`，计数 imported/skipped，缺 def 自动跳过；③ `ListPresets` 分区：官方 `FC_Recommended_*.xml`（只读随发行）与用户 `FC_Preset_*.xml`；④ 文件名消毒（待办清单项） |
| `Dialog_FacilityMatrix.cs` | 导出流程支持来源选择（来源列表 = 当前 `categories` 中 targets 的 `sourceMod` 去重）；导入菜单分区标题「作者预设 / 我的预设」 |
| `Keys.xml`（三语） | 「作者预设」分区标题、按来源导出对话框文案；可选 `FC.SourceFilter` 等 |
| 其他 | 无（Settings/Patcher/Clipboard 不动） |

## 6. 测试清单

| # | 场景 | 预期 |
|---|---|---|
| P1 | 全新档首次启动 | 各目标仅连原始链接 |
| P2 | 游戏内配置鼠族缝纫台+缝纫柜后「按来源导出鼠族」 | 文件仅含鼠族目标行；缝纫台含 `ToolCabinet` 与 `VFE_TailorCabinet` 两条 Link |
| P3 | 未装 VFE 环境导入鼠族包 | VFE_* 条 def 缺失 → skipped 计数；其余生效，无报错 |
| P4 | 导入含非法组合（目标/设施 def 不存在、目标无 AffectedByFacilities comp） | 该条跳过计数 |
| P5 | 重复导入同包 / 连续导多包 | 幂等 union，无重复无异常 |
| P6 | 导入后手动断开某格 → 再导入 | 恢复连接（SetLink true） |
| P7 | 重置（目标维/设施维/全部） | 回 originalLinks 快照，行为与现状一致 |
| P8 | 导入菜单 | 作者预设与用户预设分区显示 |
| P9 | 设施 def 存在但无 `CompProperties_Facility`（非法设施） | 该条跳过计数 |
| P10 | 位置约束（`canLinkToMedBedsOnly` / `mustBePlacedAdjacent`） | 导入不做位置预判；放置时引擎自然失败，与 XML 声明行为一致 |

## 7. 明确不做（本阶段）

- 不做 `excludedTargets` → `linkedTargets` 全量重构
- 不做 mod 自动检测与自动应用（手动导入）
- 不做类别细分代码逻辑（语义由预设作者表达）
- 不做位置级预判校验（沿用现有 def/comp/类别校验）
